# 营收自动驾驶与多模型中心：本轮冻结规格

## Objective

把当前“11 位 AI 员工演示”升级为可理解、可控制、可追踪结果的营收自动驾驶骨架；同时建立平台级多模型配置和任务路由界面，为后续接真实模型、数据库和渠道做好稳定契约。

## Current state and evidence

- 客户端已经有今日工作台、AI 指挥官、知识/视频上传、任务队列、审核、渠道和 11 位 AI 员工演示。
- 平台端已经有租户、套餐、行业模板、用量和连接器演示。
- 当前模型调用只支持 `OPENAI_API_KEY`、`OPENAI_MODEL` 和本地 mock 回退。
- 当前页面仍是锚点式长页面，上传、任务和审计仍使用本地文件演示。

## In-scope work

- 客户端增加营收自动驾驶中心：运行模式、收益目标、归因收入、商机、成本、活动和异常。
- 客户导航按真实工作任务重新命名，隐藏“逐个选择 AI 员工”的心智负担。
- 租户名称、套餐和到期时间从当前租户数据动态进入应用壳。
- 平台后台增加 AI 与自动化中心：模型连接、四种策略、员工任务路由、备用策略、预算和质量门槛。
- 增加 provider-neutral 的模型与自动驾驶 TypeScript 契约。
- PostgreSQL 草案增加目标、策略、联系人、商机、订单、归因、异常、模型提供商、模型路由和模型用量表。

## Out-of-scope work

- 不保存或展示真实 API Key。
- 不宣称已经接通任何新的模型厂商。
- 不接真实支付、订单、短视频平台、个人微信或非官方自动化。
- 不把演示收益数据描述为真实客户收入。
- 不在本轮完成数据库迁移、登录鉴权、对象存储和生产任务队列。

## Dependencies

- 生产数据库和密钥管理服务。
- 客户产品、价格、毛利、订单和退款数据。
- 模型服务的正式凭证、协议和配额。
- 渠道官方授权、Webhook 和平台审核。

## Risks

- 收益归因没有真实订单和支付数据时只能作为演示。
- 高风险行业不能直接开放无人审核的外部触达和成交动作。
- 不同模型协议并不完全一致，后续必须使用适配器和回放评测集验证。
- 页面继续保留部分旧锚点模块，真实独立路由需要在下一轮完成。

## Acceptance checks

- 客户工作台首屏能看到自动驾驶状态、四种模式、收入目标、商机、成本、系统活动和异常。
- 切换客户后应用壳中的客户、套餐和到期时间同步变化。
- 平台后台能看到 AI 与自动化导航和模型配置中心。
- 模型路由可在质量、均衡、成本和私有策略之间切换并显示保存反馈。
- 页面在桌面和 375px 级移动宽度不产生关键内容横向溢出。
- `npm run typecheck` 和 `npm run build` 通过。
- 浏览器检查客户和后台关键页面无空白、报错或主要布局破坏。

## Recommended next phase

接入本地可回放的模型网关：先支持平台主模型、一个 OpenAI-compatible 备用端点和 mock，记录每次调用的模型、成本、耗时、质量、回退与任务结果；通过固定评测集后再允许自动路由。
