# 产品规格：安全 AI 团队开发系统（阶段 1–2）

更新日期：2026-07-29

## 目标

把当前依赖长对话的 AI 辅助开发，升级为项目内可持续接管的工作方式：AI 先读取固定事实源，从统一队列中一次选择一个任务，经过风险门、实现、验证和草稿 PR 交付；用户只需要处理产品取舍和高风险批准。

## 当前状态

- 已有可运行的 Next.js 本地演示系统和公开 GitHub 仓库。
- 客户端已具备获客计划、内容草稿、人工审核、视频任务、发布包、私信动作和 CRM 跟进的本地演示链路。
- 登录存在浏览器原生表单回退修复，本轮将其纳入回归验收。
- 真实用户体系、真实渠道发布、真实 CRM、支付和生产部署尚未闭环。
- 过去的工作主要依赖对话上下文，没有统一任务队列、风险门和机器可读选择器。

## 本轮范围

### 阶段 1：事实与验收基线

- 固化产品目标、业务闭环、边界和成功标准。
- 为登录、受保护页面和客户端主链路建立可重复本地验收。
- 明确“演示已通”和“生产闭环”的差距。

### 阶段 2：AI 团队控制层

- 建立 AI 团队角色、任务队列、状态、决策日志和批准策略。
- 提供只读控制器，校验队列并且最多选择一个安全任务。
- 使用独立分支、验证证据和草稿 PR 作为交付包。

## 明确非目标

- 不创建定时自动化，不启用无人值守代码执行器。
- 不部署、不发布、不合并到 `main`。
- 不登录真实运营账号，不写入密钥，不调用真实渠道、CRM、支付或客户触达接口。
- 不把演示认证宣称为生产认证，不把素材包宣称为已真实发布。

## 依赖

- Windows PowerShell、Git、Node.js 与当前仓库依赖。
- 本地服务用于界面/API 验收；没有本地服务时，测试必须给出明确的启动提示。
- GitHub 仅用于分支与草稿 PR，不用于自动合并或发布。

## 主要风险与控制

- 上下文漂移：以仓库文档、状态和队列替代聊天记忆。
- AI 扩大范围：单任务上限、允许路径和依赖校验。
- 误触真实业务：只允许回环地址测试，外部动作始终人工门控。
- 测试污染本地演示数据：默认只运行无业务写入的 smoke；完整链路必须显式传入写入开关并使用 `e2e-` 标记。
- 假绿：同时报告类型检查、控制器验证、路由/API 结果和未覆盖的真实集成。

## 验收标准

- `TASK_QUEUE.json` 可被只读控制器完整校验。
- `next` 最多返回一个 `read_only` 且依赖满足的任务，并且不修改任何文件。
- 登录 API、客户管理员访问、客户端关键页面和只读用户写入拦截可重复验证。
- 完整本地链路测试只能面向 `127.0.0.1`/`localhost`，并要求显式 `-AllowLocalWrites`。
- 所有变更在 `codex/` 分支完成并形成草稿 PR；无部署动作。

## 下一阶段进入条件

阶段 3（隔离式自动执行）只有在本轮草稿 PR 经用户验收后才能规划。进入时仍应先实现临时工作区、修改路径检查、测试失败停机、差异审查和人工批准恢复，不直接开启部署。
