# 第三阶段规格：受控自动化

更新日期：2026-07-29

## 目标

让 Codex 每日自动处理最多一个已批准的低风险任务，同时保证用户主工作区、主分支、远端和生产环境不被自动修改。

## 当前状态与证据

- 阶段 1–2 已建立事实源、风险等级、任务队列和只读选择器。
- 登录与本地客户端闭环已有可重复 smoke/full 验收。
- `ai-4` 已存在并每日运行，但此前使用本地主工作区，只能做松散的每日小改进。
- 本机桌面 Codex 可承载自动化任务；其应用内 executable 不能作为普通 CLI 直接调用，因此阶段 3 使用 Codex Automation 的 worktree 执行环境，不自造 CLI 绕过方案。

## 本轮范围

- 队列允许 `read_only` 和 `low_risk_write` 被选择，仍然一次最多一个。
- 自动运行必须处于 Git linked worktree，禁止主工作区和 `main`/`master`。
- 修改必须完全位于任务 `allowed_paths`，禁止删除/重命名、控制文件自修改和大范围变更。
- 验证只使用代码内固定 profile，不执行队列提供的任意命令。
- 用临时 worktree 集成测试覆盖允许修改、越界拒绝、主工作区拒绝和清理。
- 将现有 `ai-4` 自动化切换为 worktree 模式和严格队列驱动提示词。

## 非目标

- 不部署、不合并、不自动提交、不推送、不创建 PR。
- 不自动执行 `controlled_write` 或 `high_risk`。
- 不安装依赖，不启动长期服务，不登录账号，不接触客户和真实渠道。
- 不实现无限重试、并行任务或自动修改风险策略。

## 依赖

- 仓库必须是 Git 工作区并支持 linked worktree。
- 自动化运行时必须能够读取本分支上的控制文件。
- 任务必须有固定 `verification_profile` 和仓库内相对 `allowed_paths`。

## 风险与回滚

- 风险：AI 修改控制文件给自己提权。控制：自动任务禁止触碰控制文件，路径门独立检查。
- 风险：队列植入任意命令。控制：验收命令仅作说明，实际只运行固定 profile。
- 风险：worktree 残留。控制：自动化由 Codex 管理 worktree；测试夹具始终在 `finally` 清理已核验临时路径。
- 回滚：将 `ai-4` 恢复为 local/只读提示词，并把队列可自动风险恢复为 `read_only`。

## 验收标准

- 队列校验通过，且 `next` 最多选择一个依赖满足的低风险任务。
- 主工作区执行变更门必定失败。
- 临时 worktree 内允许路径修改通过，越界修改必定失败。
- 固定 verification profile 通过；失败时退出码非 0。
- `ai-4` 为 ACTIVE、worktree 环境、每日 09:00，提示词明确禁止远端和部署。

## 验收后的下一阶段

先观察至少 3 次自动运行的证据质量和越界率，再决定是否加入“人工一键提交草稿 PR”。自动部署不在下一阶段默认范围内。
