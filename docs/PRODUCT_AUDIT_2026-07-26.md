# 产品体验自动审计与整改记录

日期：2026-07-26  
范围：客户工作台“查看经营状态 → 启动 AI 团队 → 暂停/恢复 → 处理人工审核”流程；SaaS 后台“查看模型连接 → 选择策略 → 保存配置”流程。

## 用户目标与可访问性目标

- 客户在进入系统后，10 秒内知道当前经营目标、唯一的下一步动作和需要人工介入的事项。
- 平台管理员能分辨“已连接、可配置、未启用”，并清楚知道配置是否已修改、是否已保存。
- 重要状态变化通过可见文本和语义状态同时表达，不只依赖颜色。
- 键盘用户可识别焦点，页面保持单一一级标题，表格结构可被辅助技术理解。

## 已确认优势

- 首屏已经从“11 个 AI 员工列表”升级为经营目标、订单归因、异常与自动化等级，商业价值更容易理解。
- 金融、交易教学、医美、中医具有独立内容、审核和渠道文案。
- 高风险动作明确保留人工确认，且平台连接边界没有宣传个人微信外挂或绕过平台风控。
- 后台模型策略采用“质量、均衡、成本、私有”四种业务语言，普通客户不需要理解模型参数。

## 问题明细、影响与整改

| 优先级 | 审计问题 | 影响 | 可靠解决方案 | 本轮状态 |
| --- | --- | --- | --- | --- |
| P0 | “暂停”按钮只改变文案，不能真正暂停任务循环 | 客户以为外部动作已停止，属于高风险信任问题 | 将暂停状态提升到指挥官流程，任务在每个安全节点等待，恢复后继续 | 已完成并实测 |
| P0 | 待命状态下“系统正在做什么”仍显示“执行中” | 状态互相矛盾，无法判断是否真的运行 | 待命时显示“今日运行计划/待启动”，运行时才显示执行中，暂停时显示安全节点暂停 | 已完成 |
| P1 | 首屏与今日工作台存在两个启动全流程按钮 | 主任务竞争，用户不确定点击哪一个 | 只保留首屏唯一启动按钮；第二个入口改为“处理 3 项待办” | 已完成 |
| P1 | 审核卡只有统一的“查看并审核” | 用户不知道应该批准、改写还是转人工 | 按风险给出“批准安全版本、转人工接管、确认发布排期”，并显示剩余决策数 | 已完成 |
| P1 | 模型后台把 3 种接入方式显示成 3 个模型连接 | 容易被理解为已经成功连接真实模型 | 改为“已连接 0/3”，未完成服务器配置前不标记为已连接 | 已完成 |
| P1 | 模型“配置”按钮没有动作 | 形成失效控件，破坏可信度 | 改为“查看要求”，展开服务器密钥、健康检查、备用切换和审计要求 | 已完成 |
| P1 | 保存按钮初始即可点击，修改后没有未保存提示 | 无法区分默认值、脏数据和已保存状态 | 建立 idle/dirty/saved 三态；只有存在变更时可保存 | 已完成 |
| P1 | 侧栏“系统设置/帮助”指向不存在的锚点 | 点击后无结果 | 替换为真实存在的“资料与权限、渠道实施帮助、平台配置、上线检查”落点 | 已完成 |
| P2 | 客户页存在两个一级标题 | 读屏与文档大纲不清晰 | 保留营收自动驾驶为唯一 H1，今日工作台降为 H2 | 已完成 |
| P2 | 模型路由使用视觉表格，但列头/单元格语义不完整 | 辅助技术难以理解列关系 | 补齐 rowgroup、columnheader、cell 语义和每个下拉框标签 | 已完成 |
| P2 | 演示营收仅在第一个指标中提示 | 其他数字可能被误解为真实经营数据 | 在首屏增加持续可见的“演示数据”标记，订单仍标注为样例订单 | 已完成 |
| P2 | 页面内容较长，多个模块仍聚合在单页 | 后续客户规模扩大时定位成本会升高 | 下一阶段拆为真实路由：内容、渠道、会话、审核、数据；保留今日工作台为跨模块摘要 | 后续架构项 |

## 审计步骤与健康度

1. 客户工作台初始状态：整改前为“基本可用”，存在状态矛盾、重复主按钮和演示数据提示不足。
2. AI 团队运行状态：整改前为“可用但控制不可靠”，暂停按钮未控制真实任务循环。
3. 人工审核与渠道区域：整改前为“信息清楚但决策动作模糊”。
4. SaaS 模型后台：整改前为“视觉清楚但连接状态和配置动作容易误导”。
5. 整改后回归：主任务、真实暂停、审核决策、连接诚实度、未保存提醒和语义结构均通过验证，健康度为“良好，可继续接真实后端”。

## 证据限制

- 本轮结合浏览器截图、DOM 结构、交互状态和源码进行审计，但没有运行完整屏幕阅读器、系统级高对比模式或 200% 缩放测试，因此不能声称完整符合 WCAG。
- 本轮没有单独捕获移动端视口，响应式结论仅来自现有 CSS 断点与桌面浏览器重排，仍需要真机复测。
- 当前模型、营收、连接状态仍是明确标注的演示配置；真实 API、数据库、支付、平台 OAuth 和消息回调不在本轮实现范围。
- 暂停控制已真实作用于本地任务循环；未来接入分布式任务队列后，需要改为服务器端 pause/cancel/checkpoint 机制。

## 下一阶段建议

将长页面拆为独立路由之前，先接入统一模型网关和 PostgreSQL，把本轮已经验证的状态机、审计记录、暂停检查点和租户策略持久化，避免 UI 与真实后台状态再次分离。
