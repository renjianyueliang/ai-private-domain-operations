# 第四阶段规格：AI 团队持续开发

更新日期：2026-07-29

## 目标

让已批准的低风险任务在独立 worktree 中形成连续流水线：选择一个任务、实现、固定验证、受控更新任务状态、提交并非强制推送到现有开发分支，使草稿 PR 自动累积可审查成果。

## 当前状态与证据

- 阶段 3 已证明 linked worktree、允许路径、越界拒绝、固定验证和失败停机有效。
- `ai-4` 已是 ACTIVE/worktree 自动化，但结果此前不提交，下一轮无法可靠继承状态。
- 草稿 PR #2 已存在并跟踪 `codex/ai-team-operating-system`，GitHub CI 已通过。

## 本轮范围

- 仅成功完成 `low_risk_write` 后，由受控脚本把该任务从 `ready` 改为 `done` 并追加证据。
- 最终差异校验确保策略、其他任务和控制代码没有被自动篡改。
- 自动化可以提交，并以非强制方式推送到现有开发分支；远端发生竞争时停止。
- 现有草稿 PR 自动获得新提交；不创建重复 PR。
- 预置一条依赖串行的低风险产品/测试队列，保证后续轮次有明确任务。
- 将运行频率提高到每 4 小时一次，每轮仍最多一个任务。

## 非目标

- 不自动合并 PR，不写 `main`，不部署。
- 不自动执行 `controlled_write`、`high_risk` 或绕过人工批准。
- 不允许自动修改策略、控制脚本、GitHub Actions、依赖、密钥或真实业务资源。
- 不并行开发多个任务，不无限重试，不强制推送。

## 依赖

- GitHub CLI 已登录，草稿 PR #2 保持开放。
- 自动化分支固定为 `codex/ai-team-operating-system`。
- 每个任务具备允许路径、固定验证 profile、依赖和回滚说明。

## 风险与回滚

- 远端竞争：普通 push 被拒绝即停，不使用 force。
- 自我提权：完成脚本只允许改变当前任务的状态、`auto_runnable` 和证据；策略及其他任务必须字节语义一致。
- 假绿：完成脚本会重新运行固定验证，失败不更新队列、不提交。
- 回滚：暂停 `ai-4`，恢复阶段 3 提示词，把分支回退到人工确认的最后提交；不影响 `main`。

## 验收标准

- 隔离夹具证明任务可以从 `ready` 受控变为 `done`。
- 最终差异门证明业务修改和唯一受控队列更新可交付，越界仍拒绝。
- 控制器能从依赖链中只选择下一个任务。
- 自动化为 ACTIVE/worktree、每 4 小时、普通 push、现有草稿 PR、无合并/部署权限。
- GitHub CI 通过。

## 后续阶段

连续运行稳定后，可增加只产生候选任务的“产品规划员”和只读“测试/安全审查员”。候选任务仍需风险分类；生产部署长期保持人工批准。
